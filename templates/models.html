Medical Screening Rationale (Recall Prioritization): In diabetes screening, a False Negative (failing to identify an undiagnosed diabetic patient) poses severe risks of unmanaged hyperglycemia, vascular damage, and clinical deterioration. Conversely, a False Positive merely prompts routine confirmatory laboratory tests (e.g., HbA1c / Oral Glucose Tolerance Test). Therefore, model selection was optimized using the F2-Score ($\beta=2$), which places twice as much weight on Recall (Sensitivity) as Precision, while penalizing excessive false alarms. The test set was strictly held out and never used for model selection, ensuring zero optimistic bias or data snooping.

🔄 Dataset Update & Retraining Instructions

To update the models when new clinical data is gathered, follow these steps:

  1. Place the updated CSV dataset in diabetes.csv or data/diabetes.csv with standard features: Pregnancies, Glucose, BloodPressure, SkinThickness, Insulin, BMI, DiabetesPedigreeFunction, Age, Outcome.
  2. Execute the automated training script from the project root: 
    py -3.10 train_model.py
  3. The script will automatically clean biologically impossible zeros, execute 5-fold cross-validation on the training set, optimize the F2-score to select the best screening pipeline, evaluate all models on the held-out test set, update model/diabetes_model.joblib, and refresh model/model_metrics.json.
  4. Restart or refresh the Flask web application to immediately apply the updated inference pipeline.
